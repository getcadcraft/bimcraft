2人が同じ建物のコピーを取ります。一方は東棟、もう一方は西棟を描き、後でその2つのコピーを1つにまとめる必要があります。2人が異なるオブジェクトに変更を加えた場合は、人が行う代わりにプログラムで統合できます。

## 仕組み

IFC ファイル内のすべての壁、ドア、階、部屋、プロパティセットには、変わらない GlobalId があります。統合は、オブジェクトをファイルが与える番号（`#123`）ではなく、この ID で探します。番号は、プログラムが保存するときに変わるためです。オブジェクトに付随し、それ自体の ID を持たない部分（配置、形状、単位）は、その内容によって比較されます。

両方のコピーは、同じ IFC バージョン（2x3、4、4.3）でなければなりません。統合は、ファイルの内容、順序、番号をそのまま維持し、新しく追加された内容のみを加えます。そのため、統合の git diff には、統合で変更された部分だけが表示されます。

## セットアップ

Git では、リポジトリごとに1回、2行の設定が必要です。

```
# .gitattributes
*.ifc merge=cadcraft

# 1回だけ、各コンピューターで実行
git config merge.cadcraft.driver "node /path/to/tools/cli/merge.mjs %O %A %B"
```

Git を使わない場合は、`cadcraft merge <base> <ours> <theirs>` を実行します。Fossil と Mercurial は、同じ3つのファイルを、それぞれのマージツールの設定で使用します。何もアップロードされません。すべてお使いのコンピューター上で実行されます。

## ルール

- 片方の側だけで変更された属性は採用されます。両方の側で同じ変更が行われた場合は、1回だけ採用されます。
- 同じ属性が2通りに変更された場合（同じ階が2通りに名前変更された場合）は**競合**です。自分の側の内容が残り、報告には両方が表示されます。結果を開き、手作業で修正してください。
- 項目の一覧（階の壁、セットのプロパティ）は、集合として統合されます。どちらかの側で追加された内容は残り、どちらかの側で削除された内容は削除されます。同じ階に、2人がそれぞれ壁を追加しても競合しません。
- どちらかの側で追加されたオブジェクトは、その形状とプロパティとともに残ります。一方の側で削除され、もう一方の側で変更されていない場合は削除されます。一方の側で削除され、もう一方の側で変更された場合は、削除され、報告されます。
- ファイルのタイムスタンプと作成者、および各オブジェクトの所有者履歴は、元のファイルの値がそのまま残ります。

形状は全体として統合されます。壁の形状は一方の側から取られ、点ごとに混ぜ合わされることはありません。圧縮された IFC ファイルと IFCX ファイルは統合されません。統合後は、保存する前に BimCraft で結果を開き、問題パネルを確認してください。
