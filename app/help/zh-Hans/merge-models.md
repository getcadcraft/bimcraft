两人各自复制了同一座建筑，一人绘制东翼，另一人绘制西翼，之后需要将两份副本合并为一。如果他们修改的是不同对象，可以由程序代替人工完成。

## 工作原理

IFC 文件中的每面墙、每扇门、每个楼层、房间和属性集都有一个永不改变的 GlobalId。合并时按该 ID 查找对象，而不是按文件给出的编号（`#123`），因为程序保存时编号会改变。没有自身 ID 的附属部分（如定位、形状和单位）则按其内容进行比较。

两份副本必须为相同的 IFC 版本（2x3、4 或 4.3）。合并会保持文件原样，包括其顺序和编号，仅添加新增内容，因此合并结果的 git diff 只显示合并所作的更改。

## 设置

Git 需要在每个仓库中设置两行（只需一次）：

```
# .gitattributes
*.ifc merge=cadcraft

# 一次性设置，在每台计算机上执行
git config merge.cadcraft.driver "node /path/to/tools/cli/merge.mjs %O %A %B"
```

不使用 git 时，运行 `cadcraft merge <base> <ours> <theirs>`。Fossil 和 Mercurial 在各自的合并工具设置中使用相同的三个文件。不会上传任何内容；全部操作均在本机上完成。

## 规则

- 只在一侧更改的属性会被保留。两侧做出相同更改时，只保留一次。
- 同一属性以两种方式更改（例如同一楼层被两人各自重命名）属于**冲突**：保留本方版本，并在报告中列出两个版本。请打开结果并手动修正。
- 一组事物（某楼层的墙、某属性集的属性）按集合合并：任一侧新增的保留，任一侧删除的移除。两人各自向同一楼层添加墙不会冲突。
- 在任一侧新增的对象会被保留，并附带其形状和属性。在一侧被删除而另一侧未改动的：删除。在一侧被删除而另一侧被修改的：删除，并在报告中列出。
- 文件的时间戳和作者，以及每个对象的所有者历史，保留本方的内容。

几何形状整体合并：墙的形状取自某一侧，绝不会逐点混合。压缩包形式的 IFC 与 IFCX 文件不参与合并。合并后，请在 BimCraft 中打开结果，并在保存前查看“问题”面板。
