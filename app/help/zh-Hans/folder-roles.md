## 文件副本状态

每个模型副本（包括主文件和编号备份）都会进行文件头检查。

| 标签 | 含义 |
|---|---|
| **完整** | 文件头和索引均位于文件之内 |
| **不完整** | 文件比其自身索引所指示的更短：复制、上传或同步时被截断，或为仍处于“仅联机”状态的云文件 |
| **无法读取** | 文件不是有效的复合文档，或无法读取 |

在**状态**列中，模型显示**完整**；当至少一个副本损坏而另一个完好时，显示琥珀色的“*n* 个不完整”；当没有任何完好副本时，显示红色的**不完整**。

## 备份

名为 `Name.0001.rvt`、`Name.0002.rvt` 等的文件是 `Name.rvt` 的编号备份。它们按所属模型分组，并按从新到旧排列，位于**全部…副本**中。当主文件完整时，卡片信息读取自主文件；否则读取自最新的完整备份（“最新完整”）。

## 角色

显示在模型名称下方的斜体中。

| 角色 | 含义 |
|---|---|
| 被*其他模型*链接：后台 | 文件夹中有其他模型链接了此模型，因此它很可能是他人的底图，例如顾问的模型 |
| 入门或未命名文件 | 名称如 Blank、Template、Default、Untitled 或 Project1：可作为起点，或为未妥善命名的文件 |
| 中心模型 | 工作共享的中心模型。工作在本地副本中进行，而不在此处 |
| 族（构件） | `.rfa` 或 `.rft` 文件：是构件，而非项目 |
| 仅备份 | 主文件已丢失，仅剩编号备份 |

## “从此处开始”的选择方式

BimCraft 采用经验用户会使用的判断逻辑：

1. 候选项为可读取的项目文件（`.rvt`、`.rte`），且未被其他模型链接，也不是入门文件。
2. 中心模型和仅备份模型只有在没有更好的选择时才会被计入。
3. 在候选项中，最近保存的文件胜出。

该框会列出其理由，并在看似最佳选择的文件已损坏、其他模型为后台模型，或所选为中心模型时发出警告。这只是一个最佳推测；请与最后编辑该项目的人员确认。

## 链接状态

| 标签 | 含义 |
|---|---|
| **在此文件夹中** | 在已保存的相对路径中找到，或在文件夹内已保存完整路径的末尾找到 |
| **找到同名文件** | 不在其路径中，但文件夹中有同名文件。请确认是否为正确的文件 |
| **库文件** | 关键字注释表或构件编码表。每台计算机随程序一并提供 |
| **不在此文件夹中** | 在整个文件夹中均未找到 |

**模型**中的**已找到的链接**列显示某模型的链接中有多少已找到，并与文件夹中应有的链接数相比较（库文件不计入）。
