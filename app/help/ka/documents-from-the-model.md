## რას გააკეთებთ

შაბლონი არის Markdown ტექსტი ველებით ორმაგ ფიგურულ ფრჩხილებში. BimCraft ავსებს ველებს ღია მოდელიდან (რაოდენობები, რაოდენობები ტიპის მიხედვით, თვისებები, თქვენი [ტეგები](topic:tags-and-schedules)) და ინახავს შედეგს PDF-ად, Word დოკუმენტად (.docx) ან Markdown-ად.

## ნაბიჯები

1. გახსენით IFC მოდელი.
2. მარცხენა პანელში, {{ui:რაოდენობები}}-ის ქვეშ, გახსენით {{ui:დოკუმენტები მოდელიდან}}.
3. აირჩიეთ შაბლონი: {{ui:კარები და ფურნიტურა}} ან {{ui:კედლები, მოპირკეთება და დასრულება}}, ან {{ui:ჩატვირთეთ შაბლონი (.md)…}} თქვენი შაბლონისთვის.
4. თუ შაბლონი კითხულობს ტეგებს, რომლებსაც მოდელი ჯერ არ განსაზღვრავს, დააწკაპუნეთ {{ui:ამ შაბლონის ტეგების დამატება}}-ზე, შემდეგ დაატეგეთ ელემენტები {{ui:ტეგები}}-ის ქვეშ.
5. შეცვალეთ ტექსტი როგორც გინდათ და დააწკაპუნეთ {{ui:დოკუმენტის ჩვენება}}-ზე.
6. დააწკაპუნეთ {{ui:PDF}}-ზე (ჯერ აირჩიეთ A4 ან Letter) ან {{ui:Word (.docx)}}-ზე.

## რას უნდა ხედავდეთ

- შევსებული დოკუმენტი ღილაკების ქვემოთ, თავისი ცხრილებით.
- გაფრთხილებების სია, როცა ველი ვერ იკითხება (ტეგი, რომელიც განსაზღვრული არ არის, თვისება, რომელსაც მოდელი არ აქვს, ბლოკი, რომელიც არასოდეს იხურება); ასეთი ველი იბეჭდება როგორც `[?…]`.
- PDF გვერდები დოკუმენტის სათაურით და „Page 1 of 3“ თითო გვერდის ბოლოში; გრძელი ცხრილები გადადის შემდეგ გვერდზე თავისი სათაურის მწკრივით.

## ველები

| ველი | რას იძლევა |
|---|---|
| `{{project}}`, `{{project description}}`, `{{file}}`, `{{date}}` | პროექტის სახელი და აღწერა, ფაილის სახელი, დღევანდელი თარიღი |
| `{{count IfcDoor}}` | რამდენი კარი |
| `{{sum IfcWall NetSideArea}}` | ჯამი, თავისი ერთეულით |
| `{{calc [sum IfcWall NetSideArea] * 1.1 round 1 unit m²}}` | არითმეტიკა (`+ - * /` და ფრჩხილები) წევრებზე კვადრატულ ფრჩხილებში: `[sum …]`, `[count …]`, ხოლო ციკლში `[qty Width]`. `round n` აყენებს ათწილადებს, `unit` ამატებს ერთეულს. რაც ვერ იკითხება ან ნულზე გაყოფაა, იბეჭდება `[?…]` და აფრთხილებს |
| `{{qty IfcWall NetSideArea by Type}}` | ცხრილი: თითო ტიპზე მწკრივი თავისი რაოდენობით და ჯამით, და ჯამის მწკრივი |
| `{{table IfcDoor cols Mark, Type, Width, tag:Fire rating}}` | ცხრილი, თითო ელემენტზე ერთი მწკრივით |
| `{{tag Finish}}` | ციკლში ელემენტის მნიშვნელობა; სხვაგან ყველა გამოყენებული მნიშვნელობა (Oak, Paint) |
| `{{tags}}` | ტეგების განსაზღვრებები ცხრილად |
| `{{#each IfcDoor}} … {{else}} … {{/each}}` | ტექსტი თითო ელემენტზე ერთხელ; ნაწილი `{{else}}`-ის შემდეგ, როცა არცერთი არ არის |
| `{{#group IfcWall by Type}} … {{/group}}` | ტექსტი თითო ტიპზე ერთხელ, `{{value}}`, `{{count}}`, `{{sum Length}}` და შიგნით ჩვეულებრივი `{{#each}}` |

`{{#each}}`-ის შიგნით: `{{name}}`, `{{type}}`, `{{storey}}`, `{{class}}`, `{{material}}`, `{{mark}}` (IFC Tag), `{{guid}}`, `{{n}}` (1, 2, 3 …), `{{prop Pset_DoorCommon.FireRating}}`, `{{qty Width}}` (ელემენტის საკუთარი, თავისი ერთეულით).

კლასი შეიძლება იყოს რამდენიმე (`IfcDoor|IfcWindow`) ან ყველა ელემენტი (`*`). შეავიწროვეთ ნებისმიერი `where`-ით: `{{#each IfcDoor where Fire rating >= 60}}`, `{{count IfcWall where Wall finish hasnot}}`. ტესტებია `=`, `!=`, `~` (შეიცავს), `>`, `<`, `>=`, `<=`, `has` და `hasnot`; რამდენიმეს `and`-ით აერთებთ; მნიშვნელობა, რომელშიც ინტერვალებია, ბრჭყალებში ჩაწერეთ. `sort Name` ახარისხებს ციკლს.

## სპეციფიკაციები და სპეციფიკაცია დოკუმენტში

`{{schedule doors}}` ბეჭდავს მოდელის სპეციფიკაციას ცხრილად, თქვენს ოფისურ განლაგებაში: `doors`, `windows`, `walls`, `rooms`, `floors`, `roomfinishes`, `wallfinishes`, `zonefinishes`, `finishtotals`, `layers`, ან იმ მოწყობის სახელი, რომელიც სპეციფიკაციებში შეინახეთ. `{{specification}}` ბეჭდავს პროექტის სპეციფიკაციას. შაბლონები **სამუშაო ნახაზების სპეციფიკაციები** და **სპეციფიკაცია** მათ იყენებს. გადახედვაში დააწკაპუნეთ ამგვარი სპეციფიკაციის ციფრზე, რომ მონიშნოთ ელემენტები, საიდანაც ის მოდის. იხილეთ [სპეციფიკაციის განლაგება, შენახვა და ექსპორტი](topic:schedule-layouts) და [სპეციფიკაციის წერა მოდელიდან](topic:specification).

## სასარგებლო ინფორმაცია

- ველი ასახელებს ჩაშენებულ მნიშვნელობას (Name, Type, Storey, Class, Material, Mark), ტეგს (`tag:Fire rating`, ან მისი სახელი), თვისებას (`Pset_WallCommon.FireRating`) ან მხოლოდ თვისების სახელს (`NetSideArea`, `Width`): შიშველი სახელი კითხულობს თითო ელემენტის საკუთარ ნაკრებს, რაოდენობრივი ნაკრებები პირველად, ასე რომ `Width` კარზე კარის სიგანეა და არა კედლის სისქე. `where`-ში შიშველი სახელი კითხულობს ნაკრებს, რომელიც არჩეულ ელემენტების უმეტესობას აქვს.
- რაოდენობები ის არის, რასაც ფაილის რაოდენობრივი ნაკრებები ამბობს (BimCraft წერს მათ იმისთვის, რასაც ხაზავს); ერთეულები მოდის ფაილის ერთეულების პარამეტრებიდან.
- ველების სიტყვები (`count`, `sum`, `qty`, `by`, `cols`, `where`, `each`, `group` …) ყველა ენაზე ინგლისურად რჩება. მაგალითი შაბლონები ინგლისურადაა.
- მოდელიდან მიღებული ტექსტი ფორმატირებად არ იქცევა: სახელი `*` ან `|` სიმბოლოთი ისე იბეჭდება, როგორიც არის.
- შეცვლილი შაბლონი შეინახეთ {{ui:შენახვა ამ ბრაუზერში}}-ით (მხოლოდ ამ ბრაუზერს აქვს) ან {{ui:შაბლონის ჩამოტვირთვა}}-ით.
- PDF ტექსტი იყენებს სტანდარტულ PDF შრიფტებს: დასავლეთ ევროპული ტექსტის გარეთ ყოველი სიმბოლო იბეჭდება როგორც „?“, და სტატუსის ხაზი გეტყვით, რამდენი.
- შაბლონები დარგის მიხედვით ბიბლიოთეკაში ცხოვრობს (ტიპი: დოკუმენტის შაბლონი). **დოკუმენტებში მოდელიდან** აირჩიეთ **ბიბლიოთეკიდან…**, აირჩიეთ ერთი და მისი ტექსტი და ტეგები, რომლებსაც ის კითხულობს, შემოდის; შეცვალეთ როგორც გინდათ. საკუთარი შაბლონის ბიბლიოთეკაში გამოქვეყნება იგივე ატვირთვაა, როგორც ნებისმიერი სხვა ელემენტისა. ჯერ არ არის აგებული: რაოდენობებსა და ჯამებს გარდა გამოთვლები.
