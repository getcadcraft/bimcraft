## អ្វីដែលអ្នកនឹងធ្វើ

ពិនិត្យថតគម្រោងមុនពេលអ្នកប្រគល់ ឬចាប់ផ្តើមការងារលើវា៖ តើម៉ូដែលនីមួយៗពេញលេញឬទេ ច្បាប់ចម្លងបម្រុងណាជាច្បាប់ល្អចុងក្រោយ ហើយតំណភ្ជាប់ឯកសារទាំងអស់មានទេ?

## ជំហាន៖ ច្បាប់ចម្លងខូច

1. បើកថតគម្រោង។ សូមមើល [បើកថតគម្រោងទាំងមូល](topic:open-project-folder)។
2. អានកំណត់សម្គាល់នៅក្រោមឈ្មោះថត។ "ឯកសារ 2 មិនពេញលេញ ឬអានមិនបាន។ សូមមើលម៉ូដែលខាងក្រោម។" មានន័យថាមានអ្វីត្រូវមើល។
3. នៅក្នុង **ម៉ូដែល** មើលជួរ **Status**។ **Complete** គឺល្អ។ "មិនពេញលេញ 1" ពណ៌ទឹកក្រូចមានន័យថាច្បាប់ចម្លងមួយខូច ប៉ុន្តែមួយទៀតនៅល្អ។ **Incomplete** ពណ៌ក្រហមមានន័យថាមិនបានរកឃើញច្បាប់ចម្លងល្អណាមួយទេ។
4. បើក **ច្បាប់ចម្លងទាំងអស់ …** នៅក្រោមម៉ូដែលដែលមានបញ្ហា។ វារាយឯកសារមេ និងច្បាប់ចម្លងបម្រុងដែលបានរាប់លេខទាំងអស់ ថ្មីបំផុតមុន ជាមួយទំហំ កាលបរិច្ឆេទ និងស្ថានភាព។
5. អានកំណត់សម្គាល់នៅខាងលើបញ្ជី ឧទាហរណ៍ "Tower.rvt មិនពេញលេញ (183.2 MB, គួរតែយ៉ាងតិច 214.0 MB)។ កាតម៉ូដែលបង្ហាញច្បាប់ចម្លងពេញលេញថ្មីបំផុត Tower.0012.rvt (Mar 3, 2025)។"
6. ចុចលើច្បាប់ចម្លងដែលអ្នកចង់បើក។ មានតែច្បាប់ចម្លងពេញលេញទេដែលអាចចុចបាន។

## អ្វីដែលការពិនិត្យសុខភាពធ្វើ

ច្បាប់ចម្លងនីមួយៗនៃម៉ូដែលនីមួយៗត្រូវបានពិនិត្យយ៉ាងឆាប់តាមផ្នែកក្បាលរបស់វា 512 bytes នីមួយៗ ដូច្នេះសូម្បីថតដែលមានម៉ូដែលធំៗក៏ត្រូវបានពិនិត្យក្នុងរយៈពេលវិនាទីដែរ។ ឯកសារណាដែលសន្ទស្សន៍របស់ខ្លួនចង្អុលហួសចុងរបស់វា ត្រូវបានកាត់ពេលកំពុងចម្លង ផ្ទុកឡើង ឬធ្វើសមកាលកម្ម។ ឯកសារក្នុងឌ្រាយវ៍ cloud ដែលនៅ "លើបណ្ដាញតែប៉ុណ្ណោះ" មើលទៅដូចគ្នា។

កាតសម្រាប់ម៉ូដែលនីមួយៗត្រូវបានអានពីឯកសារមេនៅពេលវាល្អ ហើយពីច្បាប់ចម្លងបម្រុងថ្មីបំផុតដែលល្អនៅពេលវាមិនល្អ។

## ជំហាន៖ តំណភ្ជាប់ដែលបាត់

1. ស្វែងរកកំណត់សម្គាល់ "*n* ឯកសារដែលភ្ជាប់ មិននៅក្នុងថតនេះទេ។" នៅក្រោមឈ្មោះថត។
2. រំកិលទៅ **Linked and referenced files**។ តំណភ្ជាប់ដែលបាត់ត្រូវបានរាយជាមុនគេ។
3. អានជួរ **Where** សម្រាប់តំណភ្ជាប់នីមួយៗ៖
   - **In this folder**៖ រកឃើញនៅផ្លូវដែលម៉ូដែលបានរក្សាទុក។
   - **Same name found**៖ ឯកសារដែលមានឈ្មោះដូចគ្នាស្ថិតនៅកន្លែងផ្សេងក្នុងថត។ ពិនិត្យថាវាគឺត្រឹមត្រូវ។
   - **Library file**៖ តារាងកូដ keynote ឬ assembly។ ពួកវាមកជាមួយកម្មវិធីនៅលើកុំព្យូទ័រនីមួយៗ ដូច្នេះមិនត្រូវបានរំពឹងថានៅក្នុងថតទេ។
   - **Not in this folder**៖ រកមិនឃើញនៅកន្លែងណាក្នុងថតទេ។
4. អាន **Used by** ដើម្បីមើលថាតើម៉ូដែលណាភ្ជាប់ឯកសារនីមួយៗ។

BimCraft ស្វែងរកតំណភ្ជាប់នីមួយៗជាមុនតាមផ្លូវទាក់ទងរបស់វា បន្ទាប់ដោយចុងនៃផ្លូវដែលបានរក្សាទុក (ដូច្នេះ `\\server\jobs\Tower\Cad\X-Refs\site.dwg` ត្រូវបានរកឃើញនៅ `X-Refs/site.dwg` នៅពេលអ្នកជ្រើសថត `Cad`) ហើយបន្ទាប់មកតាមឈ្មោះឯកសារនៅកន្លែងណាក៏បានក្នុងថត។

## ជំហាន៖ ឯកសារនៅសល់

1. រំកិលទៅ **Set aside** នៅចុងបំផុតនៃរបាយការណ៍។
2. អានបន្ទាត់ទាំងបីដែលអាចបង្ហាញ៖
   - ថតថែទាំ (`*_backup`, `*_log`, `Revit_temp`)៖ មិនត្រូវបានអាន។
   - ឯកសារនៅសល់សម្រាប់ lock, log និងការបម្រុង៖ ឯកសារដូចជា `.dwl`, `.dwl2`, `.bak`, `.err`, `.log`, `.tmp`, `.sv$`។ ពួកវាត្រូវបានទុកដោយកម្មវិធីដែលគាំង ឬកំពុងបើកនៅពេលថតត្រូវបានចម្លង។ ជាធម្មតាវាមានសុវត្ថិភាពក្នុងការលុប នៅពេលគ្មាននរណាម្នាក់កំពុងបើកឯកសារទាំងនោះ។
   - ឯកសារផ្សេងទៀត៖ អ្វីគ្រប់យ៉ាងផ្សេងទៀតដែល BimCraft មិនអាន។

## កំហុសទូទៅ

- **លុបឯកសារមេដែលខូចមុនពេលរក្សាទុកច្បាប់ចម្លងបម្រុងល្អ។** ចម្លងច្បាប់ចម្លងបម្រុងពេញលេញថ្មីបំផុតជាមុន រួចសឹមដោះស្រាយឯកសារដែលខូច។
- **ជឿ "Same name found" ដោយមិនពិនិត្យ។** គម្រោងពីរផ្សេងគ្នាអាចមានឈ្មោះដូចគ្នា។ បើមានការសង្ស័យ សូមបើកទាំងពីរ។
- **គិតថាឯកសារបណ្ណាល័យដែលបាត់ជាបញ្ហា។** តារាងកូដ keynote និង assembly នៅជាមួយកម្មវិធីនៅលើកុំព្យូទ័រនីមួយៗ។
- **ចំនួនឯកសារខុសគ្នារវាងកម្មវិធីរុករក។** នៅ Firefox និង Safari {{ui:បើកថត}} ផ្តល់ឯកសារគ្រប់ទាំងអស់ រួមទាំងនៅក្នុងថតថែទាំ ដូច្នេះចំនួន (និងដែនកំណត់ 20,000 ឯកសារ) រួមបញ្ចូលពួកវា។ ការអូសថតចូលរំលងពួកវា ដូចដែល Chrome និង Edge ធ្វើ។ របាយការណ៍ផ្សេងទៀតដូចគ្នា។
