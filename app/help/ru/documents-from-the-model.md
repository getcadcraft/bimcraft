## Что вы сделаете

Шаблон — это текст в Markdown с полями в двойных фигурных скобках. BimCraft заполняет поля из открытой модели (количества, количества по типам, свойства, ваши [метки](topic:tags-and-schedules)) и сохраняет результат как PDF, документ Word (.docx) или Markdown.

## Шаги

1. Откройте модель IFC.
2. На левой панели, в разделе {{ui:Количества}}, откройте {{ui:Документы из модели}}.
3. Выберите шаблон: {{ui:Двери и фурнитура}} или {{ui:Стены, облицовка и отделка}}, либо {{ui:Загрузить шаблон (.md)…}} для своего.
4. Если шаблон читает метки, которых модель еще не определяет, нажмите {{ui:Добавить метки этого шаблона}}, затем пометьте элементы в разделе {{ui:Метки}}.
5. Измените текст, как хотите, и нажмите {{ui:Показать документ}}.
6. Нажмите {{ui:PDF}} (сначала выберите A4 или Letter) или {{ui:Word (.docx)}}.

## Что должно получиться

- Заполненный документ под кнопками, с его таблицами.
- Список предупреждений, когда поле нельзя прочитать (метка не определена, свойства нет в модели, блок не закрыт); такое поле выводится как `[?…]`.
- Страницы PDF с названием документа и «Page 1 of 3» внизу каждой страницы; длинные таблицы переходят на следующую страницу с сохранением строки заголовков.

## Поля

| Поле | Выводит |
|---|---|
| `{{project}}`, `{{project description}}`, `{{file}}`, `{{date}}` | название проекта и его описание, имя файла, сегодняшнюю дату |
| `{{count IfcDoor}}` | количество дверей |
| `{{sum IfcWall NetSideArea}}` | итог с его единицей |
| `{{calc [sum IfcWall NetSideArea] * 1.1 round 1 unit m²}}` | арифметика (`+ - * /` и скобки) по членам в квадратных скобках: `[sum …]`, `[count …]`, а внутри each `[qty Width]`. `round n` задает число знаков, `unit` добавляет единицу. То, что не читается, или деление на ноль, выводится как `[?…]` с предупреждением |
| `{{qty IfcWall NetSideArea by Type}}` | таблица: строка на каждый тип с количеством и итогом, и строка общего итога |
| `{{table IfcDoor cols Mark, Type, Width, tag:Fire rating}}` | таблица, строка на каждый элемент |
| `{{tag Finish}}` | в цикле — значение элемента; в других местах — все использованные значения (Oak, Paint) |
| `{{tags}}` | определения меток в виде таблицы |
| `{{#each IfcDoor}} … {{else}} … {{/each}}` | текст один раз на каждый элемент; часть после `{{else}}`, если элементов нет |
| `{{#group IfcWall by Type}} … {{/group}}` | текст один раз на каждый тип, с `{{value}}`, `{{count}}`, `{{sum Length}}` и обычным `{{#each}}` внутри |

Внутри `{{#each}}`: `{{name}}`, `{{type}}`, `{{storey}}`, `{{class}}`, `{{material}}`, `{{mark}}` (IFC Tag), `{{guid}}`, `{{n}}` (1, 2, 3 …), `{{prop Pset_DoorCommon.FireRating}}`, `{{qty Width}}` (собственное значение элемента, с его единицей).

Класс может быть несколькими (`IfcDoor|IfcWindow`) или всеми элементами (`*`). Сузить любой из них можно через `where`: `{{#each IfcDoor where Fire rating >= 60}}`, `{{count IfcWall where Wall finish hasnot}}`. Проверки: `=`, `!=`, `~` (содержит), `>`, `<`, `>=`, `<=`, `has` и `hasnot`; несколько проверок объединяются через `and`; значение с пробелами берется в «кавычки». `sort Name` сортирует цикл.

## Ведомости и спецификация в документе

`{{schedule doors}}` выводит ведомость модели как таблицу в вашем стандарте оформления: `doors`, `windows`, `walls`, `rooms`, `floors`, `roomfinishes`, `wallfinishes`, `zonefinishes`, `finishtotals`, `layers`, либо имя набора настроек, который вы сохранили в Ведомостях. `{{specification}}` выводит спецификацию проекта. Шаблоны **Ведомости рабочих чертежей** и **Спецификация** используют их. В предпросмотре щелкните по цифре такой ведомости, чтобы выбрать элементы, из которых она взята. См. [Оформление, сохранение и экспорт ведомости](topic:schedule-layouts) и [Составление спецификации по модели](topic:specification).

## Полезно знать

- Поле называет встроенное значение (Name, Type, Storey, Class, Material, Mark), метку (`tag:Fire rating` или ее имя), свойство (`Pset_WallCommon.FireRating`) или просто имя свойства (`NetSideArea`, `Width`). Голое имя читает собственный набор каждого элемента, наборы количеств сначала, поэтому `Width` у двери — это ширина двери, а не толщина стены. Внутри `where` голое имя читает набор, который есть у большинства выбранных элементов.
- Количества — то, что говорят наборы количеств файла (BimCraft записывает их для того, что рисует); единицы берутся из настроек единиц файла.
- Слова полей (`count`, `sum`, `qty`, `by`, `cols`, `where`, `each`, `group` …) остаются на английском во всех языках. Примеры шаблонов написаны на английском.
- Текст из модели никогда не становится форматированием: имя с `*` или `|` выводится как есть.
- Сохраните измененный шаблон с помощью {{ui:Хранить в этом браузере}} (только этот браузер его хранит) или {{ui:Скачать шаблон}}.
- Текст PDF использует стандартные шрифты PDF: символ вне западноевропейского текста выводится как «?», а строка состояния сообщает, сколько их.
- Шаблоны по видам работ хранятся в Библиотеке (вид «Шаблон документа»). В разделе «Документы из модели» выберите **Из Библиотеки…**, выберите шаблон, и его текст и метки, которые он читает, загрузятся; редактируйте по своему усмотрению. Публикация своего шаблона в Библиотеку — та же загрузка, что и любого другого элемента. Еще не создано: расчеты сверх количеств и итогов.
