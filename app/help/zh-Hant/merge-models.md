兩個人各自取得同一棟建築的副本，一人繪製東翼，一人繪製西翼，之後兩份副本必須合為一份。若他們改動的是不同的物件，程式可以代替人工完成合併。

## 運作原理

IFC 檔案中的每面牆、每扇門、每個樓層、房間與特性集都有一個永不改變的 GlobalId。合併以該 id 查找物件，而非檔案給予的編號（`#123`），因為程式儲存時編號會改變。沒有自己 id 的附屬部分（配置、外形、單位）則依其所含的內容比較。

兩份副本必須是相同的 IFC 版本（2x3、4 或 4.3）。合併會保留你的檔案原樣，包括其順序與編號，並加入新的內容，因此合併結果的 git 差異只會顯示合併所改變的部分。

## 設定

Git 每個儲存庫需要設定兩行，只需一次：

```
# .gitattributes
*.ifc merge=cadcraft

# 每台電腦各設定一次
git config merge.cadcraft.driver "node /path/to/tools/cli/merge.mjs %O %A %B"
```

不使用 git 時，請執行 `cadcraft merge <base> <ours> <theirs>`。Fossil 與 Mercurial 會以其各自合併工具的設定，接受相同的三個檔案。一切都不會上傳；全部在你的電腦上執行。

## 規則

- 只在一側變更的屬性會被採用。兩側做出相同的變更時，只採用一次。
- 同一個屬性以兩種方式變更（同一樓層以兩種方式重新命名）為**衝突**：保留你這一側，報告會列出兩者。請開啟結果並手動修正。
- 一份清單（某樓層的牆、某特性集的特性）會以集合的方式合併：任一側新增的內容都會保留，任一側移除的內容都會移除。兩人各自在同一樓層新增牆，不會產生衝突。
- 任一側新增的物件會保留，並附帶其外形與特性。一側移除、另一側未變更：移除。一側移除、另一側有變更：移除，並加以報告。
- 檔案的時間戳記與作者，以及每個物件的擁有者歷程，都保留為你的。

幾何會整體合併：牆的外形取自其中一側，絕不會逐點混合。壓縮的 IFC 與 IFCX 檔案不會合併。合併後，請在 BimCraft 中開啟結果，並在儲存前查看問題面板。
