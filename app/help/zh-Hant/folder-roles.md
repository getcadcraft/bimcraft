## 複本狀態

每個模型的每一份複本（包括主檔與編號備份）都會進行標頭檢查。

| 標籤 | 意義 |
|---|---|
| **完整** | 檔案的標頭與索引都位於檔案範圍之內 |
| **不完整** | 檔案比其自身索引所記錄的長度還短：複製、上傳或同步時被截斷，或是仍為「僅線上」狀態的雲端檔案 |
| **無法讀取** | 檔案不是有效的複合檔案，或無法讀取 |

在**狀態**欄中，模型若至少有一份複本損壞但另一份完好，會顯示琥珀色的「*n* 份不完整」；若沒有任何完好的複本，則以紅色顯示**不完整**。模型若所有複本皆完整，則顯示**完整**。

## 備份

名為 `Name.0001.rvt`、`Name.0002.rvt` 等的檔案是 `Name.rvt` 的編號備份。它們會依其模型分組，並以最新者在前的順序列在**所有 … 份複本**中。若主檔完整，卡片資訊會取自主檔；否則取自最新的完整備份（「最新完整」）。

## 角色

顯示於模型名稱下方的斜體字。

| 角色 | 意義 |
|---|---|
| 由*其他模型*連結：背景 | 資料夾中有另一個模型連結到此模型，因此它很可能是他人的背景模型，例如顧問的模型 |
| 起始檔或未命名檔案 | 名稱如 Blank、Template、Default、Untitled 或 Project1：可作為起點，或是從未正式命名的檔案 |
| 中央模型 | 工作共用的中央模型。實際作業在本機複本中進行，而非此處 |
| 族（零件） | `.rfa` 或 `.rft` 檔案：元件，而非專案 |
| 僅有備份 | 主檔已遺失，只剩下編號備份 |

## 「從這裡開始」如何選擇

BimCraft 採用資深使用者會套用的判斷方式：

1. 候選者為可讀取的專案檔（`.rvt`、`.rte`），且未被其他模型連結，也不是起始檔。
2. 中央模型與僅有備份的模型只有在沒有更好的選擇時才會列入。
3. 在候選者中，最近儲存的那一個勝出。

方塊會列出選擇的理由，並在看似最明顯的選擇已損壞、其他模型為背景，或所選為中央模型時發出警告。這只是最佳猜測；請向最後處理此專案的人確認。

## 連結狀態

| 標籤 | 意義 |
|---|---|
| **在此資料夾中** | 在保存的相對路徑中找到，或在資料夾內保存的完整路徑末端找到 |
| **找到同名檔案** | 不在其路徑中，但資料夾中有同名檔案。請確認是否為正確的檔案 |
| **程式庫檔案** | 關鍵字註記或組合代碼表。它們隨程式附於每台電腦 |
| **不在此資料夾中** | 在資料夾中任何位置都找不到 |

**模型**中的**找到的連結**欄，會顯示在資料夾中預期的連結裡找到了模型的多少個（程式庫檔案不計算在內）。

## 略過的項目

| 項目 | 意義 |
|---|---|
| Revit 維護資料夾（不讀取） | `*_backup`、`*_log` 與 `Revit_temp` 資料夾，以及隱藏資料夾與 `__MACOSX` |
| 鎖定、記錄與備份殘留檔 | `.dwl`、`.dwl2`、`.bak`、`.err`、`.log`、`.tmp`、`.sv$`、`.ac$`、`.lck` 與 `.slog` 檔案 |
| 其他檔案 | 其餘所有檔案（前 40 個會列出名稱） |
