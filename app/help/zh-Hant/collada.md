工具列上的{{ui:Collada}}（或功能表與功能區樣式中「檔案」功能表內的{{ui:匯出 Collada (.dae, .kmz)…}}）會將目前開啟的內容寫入為 Collada 1.4.1：所有顯示中的模型，聯合的模型則依你放置的位置寫入。

## 匯出

1. 選擇{{ui:Collada}}。
2. 選取格式：
   - {{ui:Collada 檔案 (.dae)，供 Blender 及其他 3D 程式使用}}。
   - {{ui:Google Earth 套件 (.kmz)：模型置於地圖上的實際位置}}。僅在模型具有位置時才會提供。
3. 選擇選項，再按{{ui:匯出}}。檔案會下載，狀態列會顯示寫入了多少個元素。

| 選項 | 作用 |
|---|---|
| {{ui:將位置寫入檔案}} | 將檔案原點的緯度、經度、高度與方位角加入 .dae |
| {{ui:高度}} | {{ui:貼地：模型的 0 層標高位於地形上}}，或{{ui:模型本身的海拔高度}} |
| {{ui:包含房間與空間}} | 空間也會一併寫入（預設不包含） |
| {{ui:包含隱藏元素}} | 你隱藏的元素也會一併寫入（預設只寫入可見的內容） |

## 檔案內容

| 模型中的內容 | Collada 檔案中的內容 |
|---|---|
| 建築、樓層 | 巢狀節點，樓層依標高順序排列；不在任何樓層的元素放在「未放置」之下 |
| 每個元素 | 一個節點，含其自己的網格，名稱與模型中相同（有名稱則用名稱，否則用類別與標籤） |
| 類別、GlobalId、預先定義類型 | 位於節點的額外資料中（IFC 設定檔），並使用完整名稱（ModelCraft 設定檔） |
| 色彩 | 材料，含透明度 |
| 單位與座標軸 | 公尺，Z 軸朝上。前景模型的 0 層位於高度 0 |

模型會靠近原點放在地面上，因此以單精度運作的程式也能穩定顯示，不會抖動。ModelCraft 以相同的寫入程式產生 Collada 檔案，並會以元素名稱開啟這些檔案。

## 位置來源

前景模型提供位置，計算方式與{{ui:量測}}計算點的緯度與經度相同：

- 地圖轉換（IFC4 IfcMapConversion，或 IFC2X3 屬性集），透過模型的座標系統。你為模型選取的系統優先於檔案中指定的系統。
- 否則使用基地的緯度與經度（為近似值，對整個基地而言已足夠）。

方位角是量測而得，並非假設：會考量地圖的旋轉、真北與地圖的子午線收斂角。要為模型設定位置，請在{{ui:量測}}中使用{{ui:地圖原點…}}。

## 在其他程式中

- **Google Earth** 會讀取 .kmz：模型會出現在該位置，並朝向北方。一般的 .dae 沒有 Google Earth 可讀取位置的地方；請使用 .kmz。
- **Blender**（4.x 及更早版本）：File、Import、Collada (.dae)。每個元素會以各自的物件連同其材料匯入。位置保存在檔案的額外資料中，Blender 不會讀取。Blender 5.0 已移除內建的 Collada 匯入功能；此時請改用{{ui:USD}}或 glTF 匯出，或在 Blender 4.5 中開啟 .dae 並儲存為 .blend。

我們的測試會以 Collada 1.4.1 結構描述檢查每個檔案，並以獨立的 Collada 讀取器讀回。我們尚未在 Blender 或 Google Earth 中開啟過這些檔案。
