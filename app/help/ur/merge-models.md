دو لوگ ایک ہی عمارت کی کاپی لیتے ہیں، ایک مشرقی ونگ ڈرا کرتا ہے اور دوسرا مغربی، اور بعد میں کاپیوں کو ایک ہونا پڑتا ہے۔ اگر انہوں نے مختلف آبجیکٹس کو چھوا ہو تو یہ کام ایک پروگرام کر سکتا ہے، کسی شخص کے بجائے۔

## یہ کیسے کام کرتا ہے

IFC فائل میں ہر دیوار، دروازے، لیول، کمرے اور پراپرٹی سیٹ کا ایک GlobalId ہوتا ہے جو کبھی نہیں بدلتا۔ ملاپ آبجیکٹس کو اسی آئی ڈی سے ڈھونڈتا ہے، فائل کے دیے گئے نمبر (`#123`) سے نہیں، کیونکہ پروگرام محفوظ کرتے وقت نمبر بدل دیتے ہیں۔ آبجیکٹ سے لٹکے ہوئے وہ حصے جن کی اپنی کوئی آئی ڈی نہیں (پلیسمنٹس، شیپس، یونٹس) ان کے مواد سے موازنہ کیے جاتے ہیں۔

دونوں کاپیاں IFC کے ایک ہی ورژن کی ہونی چاہئیں (2x3، 4 یا 4.3)۔ ملاپ آپ کی فائل کو جیسی ہے ویسی رکھتا ہے، اس کی ترتیب اور نمبروں سمیت، اور جو نیا ہے وہ شامل کرتا ہے، اس لیے ملاپ کا git diff صرف وہی دکھاتا ہے جو ملاپ نے بدلا۔

## سیٹ اپ

Git کو ہر ریپوزٹری میں ایک بار دو لائنیں چاہئیں:

```
# .gitattributes
*.ifc merge=cadcraft

# ہر کمپیوٹر پر ایک بار
git config merge.cadcraft.driver "node /path/to/tools/cli/merge.mjs %O %A %B"
```

Git کے بغیر `cadcraft merge <base> <ours> <theirs>` چلائیں۔ Fossil اور Mercurial وہی تین فائلیں اپنی مرج ٹول سیٹنگ میں لیتے ہیں۔ کچھ اپ لوڈ نہیں ہوتا؛ سب کچھ آپ کے کمپیوٹر پر چلتا ہے۔

## قواعد

- کسی صفت میں تبدیلی صرف ایک طرف ہو تو وہی لی جاتی ہے۔ دونوں طرف ایک ہی تبدیلی ہو تو ایک بار لی جاتی ہے۔
- ایک ہی صفت دو مختلف طریقوں سے بدلی جائے (ایک ہی لیول کا دو طرح نام بدلا جائے) تو یہ **تصادم** ہے: آپ کا فریق برقرار رہتا ہے اور رپورٹ دونوں درج کرتی ہے۔ نتیجہ کھولیں اور خود ٹھیک کریں۔
- چیزوں کی فہرست (کسی لیول کی دیواریں، کسی سیٹ کی پراپرٹیز) ایک سیٹ کے طور پر ملتی ہے: جو کسی بھی طرف شامل ہوا وہ رہتا ہے، اور جو کسی بھی طرف ہٹایا گیا وہ ہٹ جاتا ہے۔ ایک ہی لیول میں دیواریں شامل کرنے والے دو لوگوں میں تصادم نہیں ہوتا۔
- کسی بھی طرف شامل آبجیکٹ اپنی شیپ اور پراپرٹیز کے ساتھ رہتا ہے۔ ایک طرف سے ہٹایا گیا اور دوسری طرف بدلا نہ گیا: ہٹ جاتا ہے۔ ایک طرف سے ہٹایا گیا اور دوسری طرف بدلا گیا: ہٹ جاتا ہے، اور رپورٹ ہوتا ہے۔
- فائل کا ٹائم اسٹیمپ اور مصنف، اور ہر آبجیکٹ کی اونر ہسٹری، آپ کے ہی رہتے ہیں۔

جیومیٹری پوری ملائی جاتی ہے: کسی دیوار کی شیپ ایک طرف سے آتی ہے، نقطہ بہ نقطہ کبھی نہیں ملائی جاتی۔ زپ شدہ IFC اور IFCX فائلیں ملائی نہیں جاتیں۔ ملاپ کے بعد، محفوظ کرنے سے پہلے، نتیجے کو BimCraft میں کھولیں اور مسائل پینل دیکھیں۔
