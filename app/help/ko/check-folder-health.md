## 할 일

프로젝트를 인계하거나 작업을 시작하기 전에 프로젝트 폴더를 확인합니다. 모든 모델이 온전한지, 마지막으로 정상이던 백업이 무엇인지, 연결된 파일이 모두 있는지 확인합니다.

## 단계: 손상된 복사본

1. 프로젝트 폴더를 엽니다. [프로젝트 폴더 전체 열기](topic:open-project-folder)를 참조하십시오.
2. 폴더 이름 아래의 안내를 읽습니다. "파일 2개가 불완전하거나 읽을 수 없습니다. 아래 모델을 확인하십시오."라는 안내가 보이면 확인할 항목이 있다는 뜻입니다.
3. **모델** 목록의 **상태** 열을 봅니다. **완료**는 정상입니다. 주황색 "불완전 1개"는 한 복사본은 손상되었지만 다른 복사본은 온전하다는 뜻입니다. 빨간색 **불완전**은 온전한 복사본을 찾지 못했다는 뜻입니다.
4. 문제가 있는 모델 아래의 **모든 … 복사본**을 엽니다. 기본 파일과 번호가 붙은 모든 백업을 최신순으로, 크기, 날짜, 상태와 함께 나열합니다.
5. 목록 위의 안내를 읽습니다. 예: "Tower.rvt가 불완전합니다(183.2 MB, 최소 214.0 MB여야 함). 카드에는 가장 최근의 온전한 복사본인 Tower.0012.rvt(2025년 3월 3일)가 표시됩니다."
6. 열고 싶은 복사본을 클릭합니다. 온전한 복사본만 클릭할 수 있습니다.

## 상태 검사의 동작

모든 모델의 모든 복사본은 머리글(각 512바이트)을 빠르게 검사하므로, 대용량 모델이 많은 폴더도 몇 초면 검사됩니다. 파일 자체의 색인이 파일 끝을 넘어서는 파일은 복사, 업로드 또는 동기화 도중 잘린 것입니다. 클라우드 드라이브에서 아직 "온라인 전용"인 파일도 같은 방식으로 보입니다.

각 모델의 카드는 기본 파일이 온전하면 기본 파일에서, 그렇지 않으면 가장 최근의 온전한 백업에서 정보를 읽습니다.

## 단계: 끊어진 링크

1. 폴더 이름 아래의 "*n*개의 연결 파일이 이 폴더에 없습니다." 안내를 찾습니다.
2. **연결 및 참조 파일**로 스크롤합니다. 끊어진 링크가 먼저 나열됩니다.
3. 각 링크의 **위치** 열을 읽습니다.
   - **이 폴더 안**: 모델이 저장한 경로에서 찾았습니다.
   - **같은 이름 찾음**: 같은 이름의 파일이 폴더 안의 다른 위치에 있습니다. 올바른 파일인지 확인하십시오.
   - **라이브러리 파일**: 키노트 또는 어셈블리 코드 표입니다. 이 파일은 각 컴퓨터에 프로그램과 함께 설치되므로 폴더에 있을 것으로 예상하지 않습니다.
   - **이 폴더에 없음**: 폴더 어디에서도 찾지 못했습니다.
4. **사용처**를 읽어 각 파일을 연결하는 모델을 확인합니다.

BimCraft는 각 링크를 먼저 상대 경로로, 다음으로 저장된 경로의 끝부분으로(예: `\\server\jobs\Tower\Cad\X-Refs\site.dwg`는 `Cad` 폴더를 선택했을 때 `X-Refs/site.dwg`에서 찾습니다), 마지막으로 폴더 안 어디에서든 파일 이름으로 찾습니다.

## 단계: 잔여 파일

1. 보고서 끝의 **따로 보관** 항목으로 스크롤합니다.
2. 나타날 수 있는 세 줄을 읽습니다.
   - 관리용 폴더(`*_backup`, `*_log`, `Revit_temp`): 읽지 않습니다.
   - 잠금, 로그, 백업 잔여 파일: `.dwl`, `.dwl2`, `.bak`, `.err`, `.log`, `.tmp`, `.sv$` 같은 파일입니다. 비정상 종료된 프로그램이나 폴더를 복사할 때 열려 있던 프로그램이 남긴 파일입니다. 아무도 파일을 열고 있지 않으면 보통 삭제해도 안전합니다.
   - 기타 파일: BimCraft가 읽지 않는 나머지 모든 파일입니다.

## 자주 하는 실수

- **온전한 백업을 먼저 저장하지 않고 손상된 기본 파일을 삭제하는 것.** 먼저 가장 최근의 온전한 백업을 복사한 다음 손상된 파일을 처리하십시오.
- **"같은 이름 찾음"을 무조건 믿는 것.** 서로 다른 도면이 같은 이름을 가질 수 있습니다. 확실하지 않으면 두 파일을 모두 여십시오.
- **누락된 라이브러리 파일을 문제로 여기는 것.** 키노트와 어셈블리 코드 표는 각 컴퓨터의 프로그램과 함께 있습니다.
- **브라우저마다 파일 수가 다른 것.** Firefox와 Safari에서는 {{ui:폴더 열기}}를 사용하면 관리용 폴더 안의 파일을 포함한 모든 파일이 전달되므로, 파일 수(와 20,000개 제한)에 이 파일들이 포함됩니다. 폴더를 끌어다 놓으면 Chrome과 Edge처럼 이 파일들을 건너뜁니다. 그 밖의 보고서 내용은 같습니다.
