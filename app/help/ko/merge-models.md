두 사람이 같은 건물을 복사하여, 한 명은 동쪽 동을, 다른 한 명은 서쪽 동을 그립니다. 나중에는 두 복사본을 하나로 합쳐야 합니다. 서로 다른 객체를 건드렸다면 사람 대신 프로그램이 이를 처리할 수 있습니다.

## 작동 원리

IFC 파일의 모든 벽, 문, 층, 실, 속성 세트에는 바뀌지 않는 GlobalId가 있습니다. 병합은 객체를 파일이 부여한 번호(`#123`)가 아니라 이 ID로 찾습니다. 프로그램이 저장할 때 번호가 바뀌기 때문입니다. 자체 ID가 없는 객체의 부속 요소(배치, 형상, 단위)는 담고 있는 내용으로 비교합니다.

두 복사본은 같은 IFC 버전(2x3, 4 또는 4.3)이어야 합니다. 병합은 자신의 파일을 그대로 유지하며 순서와 번호도 그대로 둔 채 새로운 내용을 추가합니다. 따라서 병합 결과의 git 차이에는 병합으로 바뀐 부분만 나타납니다.

## 설정

Git에는 저장소마다 한 번 다음 두 줄이 필요합니다.

```
# .gitattributes
*.ifc merge=cadcraft

# 컴퓨터마다 한 번
git config merge.cadcraft.driver "node /path/to/tools/cli/merge.mjs %O %A %B"
```

Git을 사용하지 않는다면 `cadcraft merge <base> <ours> <theirs>`를 실행하십시오. Fossil 및 Mercurial도 각자의 병합 도구 설정에서 같은 세 파일을 사용합니다. 아무것도 업로드하지 않으며, 모든 작업은 사용자의 컴퓨터에서 실행됩니다.

## 규칙

- 한쪽에서만 바뀐 속성은 그대로 채택됩니다. 양쪽에서 같은 변경을 했다면 한 번만 채택됩니다.
- 같은 속성이 두 가지 방식으로 바뀌었다면(같은 층의 이름을 두 가지로 바꾼 경우) **충돌**입니다. 자신의 쪽이 유지되고, 보고서에 두 값이 모두 나열됩니다. 결과를 열어 직접 고치십시오.
- 목록(층의 벽, 세트의 속성)은 집합으로 병합됩니다. 어느 한쪽이 추가한 항목은 유지되고, 어느 한쪽이 삭제한 항목은 삭제됩니다. 같은 층에 벽을 각자 추가한 두 사람은 충돌하지 않습니다.
- 한쪽에서 추가한 객체는 형상과 속성을 포함하여 유지됩니다. 한쪽에서 삭제되고 다른 쪽에서는 그대로인 객체는 삭제됩니다. 한쪽에서 삭제되고 다른 쪽에서 바뀐 객체는 삭제되며 보고됩니다.
- 파일의 작성 시각과 작성자, 그리고 각 객체의 소유자 기록은 자신의 것으로 유지됩니다.

형상은 통째로 병합됩니다. 벽의 형상은 한쪽에서만 가져오며, 점 단위로 섞이지 않습니다. 압축된 IFC 및 IFCX 파일은 병합하지 않습니다. 병합 후에는 저장하기 전에 BimCraft에서 결과를 열고 문제 패널을 확인하십시오.
