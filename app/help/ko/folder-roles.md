## 복사본 상태

모델의 모든 복사본(주 파일과 번호가 붙은 백업 모두)에 헤더 검사를 합니다.

| 레이블 | 의미 |
|---|---|
| **완료** | 파일의 헤더와 색인이 파일 안에 들어 있습니다 |
| **불완전** | 파일이 자체 색인이 말하는 것보다 짧습니다. 복사, 업로드 또는 동기화 중에 잘렸거나, 아직 "온라인 전용"인 클라우드 파일입니다 |
| **읽을 수 없음** | 유효한 복합 파일이 아니거나 읽을 수 없었습니다 |

**상태** 열에서 모델은 **완료**로 표시됩니다. 복사본 중 하나 이상이 불량이고 다른 복사본은 정상이면 주황색 "*n* 불완전"으로, 정상인 복사본이 없으면 빨간색 **불완전**으로 표시됩니다.

## 백업

`Name.0001.rvt`, `Name.0002.rvt` 등의 이름을 가진 파일은 `Name.rvt`의 번호가 붙은 백업입니다. 이 파일들은 모델 아래에 최신 순으로 **모든 … 복사본**에 묶여 표시됩니다. 카드는 주 파일이 완전하면 주 파일에서, 그렇지 않으면 가장 최근의 완전한 백업("newest complete")에서 읽습니다.

## 역할

모델 이름 아래에 기울임꼴로 표시됩니다.

| 역할 | 의미 |
|---|---|
| *다른 모델*이 링크함: 배경 | 폴더의 다른 모델이 이 모델을 링크하고 있어, 컨설턴트의 모델처럼 다른 사람의 배경일 가능성이 큽니다 |
| 시작 파일 또는 이름 없는 파일 | Blank, Template, Default, Untitled 또는 Project1 같은 이름입니다. 시작점이거나 제대로 이름이 붙지 않은 파일입니다 |
| 중앙 모델 | 작업 공유 중앙 모델입니다. 작업은 여기가 아니라 로컬 복사본에서 이루어집니다 |
| 패밀리(부품) | `.rfa` 또는 `.rft` 파일입니다. 프로젝트가 아니라 구성요소입니다 |
| 백업만 | 주 파일은 없고 번호가 붙은 백업만 남아 있습니다 |

## 여기서 시작 선택 방식

BimCraft는 숙련된 사용자가 하는 판단과 같은 추론을 적용합니다:

1. 후보는 다른 모델이 링크하지 않고 시작 파일이 아닌, 읽을 수 있는 프로젝트 파일(`.rvt`, `.rte`)입니다.
2. 중앙 모델과 백업만 있는 모델은 더 나은 것이 없을 때만 후보가 됩니다.
3. 후보 중 가장 최근에 저장된 파일이 선택됩니다.

상자에는 선택 이유가 나열되며, 가장 그럴듯해 보이는 파일이 손상되어 있거나, 다른 모델이 배경이거나, 선택된 것이 중앙 모델이면 경고합니다. 이는 최선의 추정이므로 프로젝트를 마지막으로 작업한 사람에게 확인합니다.

## 링크 상태

| 레이블 | 의미 |
|---|---|
| **이 폴더에 있음** | 저장된 상대 경로에서 찾았거나, 폴더 안의 저장된 전체 경로 끝에서 찾았습니다 |
| **같은 이름 발견** | 저장된 경로에는 없지만 같은 이름의 파일이 폴더에 있습니다. 올바른 파일인지 확인합니다 |
| **라이브러리 파일** | 키노트 또는 어셈블리 코드 표입니다. 각 컴퓨터에 프로그램과 함께 제공됩니다 |
| **이 폴더에 없음** | 폴더 어디에서도 찾지 못했습니다 |

**모델**의 **찾은 링크** 열에는 폴더에 있을 것으로 예상되는 링크 가운데 모델의 링크가 몇 개 찾아졌는지 표시됩니다(라이브러리 파일은 계산하지 않습니다).
