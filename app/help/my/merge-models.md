လူနှစ်ယောက်က အဆောက်အအုံတူတစ်ခု၏ မိတ္တူယူသည်၊ တစ်ယောက်က အရှေ့ပိုင်းကို ဆွဲပြီး တစ်ယောက်က အနောက်ပိုင်းကို ဆွဲသည်၊ နောက်ပိုင်းတွင် မိတ္တူနှစ်ခုကို တစ်ခုတည်း ဖြစ်စေရမည်။ ၎င်းတို့က မတူသော object များကို ထိခဲ့လျှင် လူအစား program က ပြုလုပ်နိုင်သည်။

## အလုပ်လုပ်စေသည့်အရာ

IFC ဖိုင်ရှိ နံရံ၊ တံခါး၊ level၊ အခန်းနှင့် property set တိုင်းတွင် တစ်ခါမှ မပြောင်းသော GlobalId ရှိသည်။ ပေါင်းစပ်မှုက object များကို ဖိုင်က ပေးထားသော နံပါတ် (`#123`) ဖြင့် မဟုတ်ဘဲ ထို id ဖြင့် ရှာသည်၊ အကြောင်းမှာ program သိမ်းသောအခါ နံပါတ်များ ပြောင်းသွားသောကြောင့်ဖြစ်သည်။ ကိုယ်ပိုင် id မရှိသော object မှ ချိတ်ဆွဲထားသည့် အစိတ်အပိုင်းများ (placement၊ shape၊ unit) ကို ၎င်းတို့ ပါဝင်သည့်အရာဖြင့် နှိုင်းယှဉ်သည်။

မိတ္တူနှစ်ခုစလုံး IFC ဗားရှင်း တူရမည် (2x3၊ 4 သို့မဟုတ် 4.3)။ ပေါင်းစပ်မှုက သင့်ဖိုင်ကို ၎င်းအတိုင်း၊ ၎င်း၏ အစဉ်နှင့် နံပါတ်များဖြင့် ထိန်းထားပြီး အသစ်ဖြစ်သည်များကို ထည့်သည်၊ ထို့ကြောင့် ပေါင်းစပ်မှု၏ git diff က ပေါင်းစပ်မှု ပြောင်းလဲသည့်အရာကိုသာ ပြသည်။

## စတင်တပ်ဆင်ခြင်း

Git သည် repository တစ်ခုလျှင် တစ်ကြိမ် စာကြောင်းနှစ်ကြောင်း လိုအပ်သည်:

```
# .gitattributes
*.ifc merge=cadcraft

# တစ်ကြိမ်၊ ကွန်ပျူတာတစ်လုံးစီတွင်
git config merge.cadcraft.driver "node /path/to/tools/cli/merge.mjs %O %A %B"
```

git မပါဘဲ `cadcraft merge <base> <ours> <theirs>` ကို run ပါ။ Fossil နှင့် Mercurial သည် ၎င်းတို့၏ merge-tool ဆက်တင်တွင် ဖိုင်သုံးခုတူ ယူသည်။ ဘာမျှ upload မလုပ်ပါ; အားလုံးသည် သင့်ကွန်ပျူတာပေါ်တွင် အလုပ်လုပ်သည်။

## စည်းမျဉ်းများ

- ဘက်တစ်ဘက်တည်းတွင် ပြောင်းထားသော attribute ကို ယူသည်။ နှစ်ဘက်စလုံးတွင် တူညီသော ပြောင်းလဲမှုကို တစ်ကြိမ်သာ ယူသည်။
- attribute တစ်ခုကို နည်းနှစ်မျိုးဖြင့် ပြောင်းထားလျှင် (level တစ်ခုကို အမည် နည်းနှစ်မျိုးဖြင့် ပြောင်းသည်) **ပဋိပက္ခ** ဖြစ်သည်: သင့်ဘက်က ကျန်ပြီး အစီရင်ခံစာက နှစ်ခုလုံးကို စာရင်းပြုသည်။ ရလဒ်ကို ဖွင့်ပြီး လက်ဖြင့် ပြင်ပါ။
- အရာများ၏ စာရင်း (level ၏ နံရံများ၊ set ၏ ဂုဏ်သတ္တိများ) သည် set တစ်ခုအဖြစ် ပေါင်းစပ်သည်: ဘက်တစ်ဘက်က ထည့်သမျှ ထိန်းထားပြီး ဘက်တစ်ဘက်က ဖယ်သမျှ ဖယ်ရှားသည်။ လူနှစ်ဦးစလုံးက တူညီသော level သို့ နံရံ ထည့်ခြင်းသည် ပဋိပက္ခ မဖြစ်ပါ။
- ဘက်တစ်ဘက်ဘက်တွင် ထည့်ထားသော object ကို ၎င်း၏ shape နှင့် ဂုဏ်သတ္တိများဖြင့် ထိန်းထားသည်။ တစ်ဘက်တွင် ဖယ်ထားပြီး အခြားဘက်တွင် မထိသည်: ဖယ်ရှားသည်။ တစ်ဘက်တွင် ဖယ်ထားပြီး အခြားဘက်တွင် ပြောင်းထားသည်: ဖယ်ရှားပြီး အစီရင်ခံသည်။
- ဖိုင်၏ အချိန်တံဆိပ်နှင့် ရေးသားသူ၊ object တစ်ခုစီ၏ owner history တို့သည် သင့်ဘက်တွင် ကျန်ရှိသည်။

ဂျီသြမေတြီကို အပြည့်အစုံ ပေါင်းစပ်သည်: နံရံ၏ shape သည် ဘက်တစ်ဘက်မှ လာသည်၊ အမှတ်တစ်ခုချင်းစီ ရောမွှေခြင်း ဘယ်တော့မှ မရှိပါ။ Zip ပြုလုပ်ထားသော IFC နှင့် IFCX ဖိုင်များကို ပေါင်းစပ်ခြင်း မရှိပါ။ ပေါင်းစပ်ပြီးနောက် BimCraft တွင် ရလဒ်ကို ဖွင့်ပြီး သိမ်းခင် ပြဿနာများ panel ကို ကြည့်ပါ။
