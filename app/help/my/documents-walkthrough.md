## ဘာလုပ်မလဲ

သင်သည် Ana ဖြစ်ပြီး လုပ်ဖော်ကိုင်ဖက် Ben နှင့်အတူ Riverside Clinic ပေါ်တွင် အလုပ်လုပ်သည်။ ပရောဂျက်၏ IFC မော်ဒယ်များသည် သင်နှစ်ဦးစလုံး ဝင်ရောက်နိုင်သော ဖိုင်တွဲတစ်ခုတွင် ရှိသည် (shared drive၊ sync ဖိုင်တွဲ၊ သို့မဟုတ် cloud ဖိုင်တွဲ)။ အဆုံးတွင် ဖိုင်တစ်ခုသည် ပထမမိတ္တူမှ ထုတ်ပြန်ပြီး ပြင်ဆင်မှု **A** သို့ ရောက်ပြီး၊ ထပ်မံ **B.1** အဖြစ် ပြောင်းလဲပြီး၊ ဘယ်သူက ဘာလုပ်သလဲ မြင်ပြီး၊ သင်ဖိုင်ကို ကိုင်ထားစဉ် Ben က ဘာမြင်သလဲ မြင်ရမည်။

အရာအားလုံးကို သင့်ဖိုင်များဘေးရှိ ဝှက်ထားသော `.ccvault` ဖိုင်တွဲတွင် သိမ်းသည်: ဆာဗာ မရှိ၊ ဘာမျှ မတင်ပါ (cloud ဖိုင်တွဲမှာ ချွင်းချက်ဖြစ်သည်၊ နောက်ဆုံးအဆင့်ကို ကြည့်ပါ)။ ခလုတ်နှင့် စည်းမျဉ်းအားလုံးကို တစ်နေရာတည်းတွင် ကြည့်ရန်၊ သင့် app တွင် ရှိလျှင် *စာရွက်စာတမ်းများ- check out၊ ပြင်ဆင်မှုနှင့် ထုတ်ပြန်ခြင်း* ဟူသော အကြောင်းအရာကို ကြည့်ပါ။

## ၁။ ပရောဂျက်ဖိုင်တွဲကို စီစဉ်ပါ

1. စတင်စခရင်ရှိ {{ui:Open a folder}} ဘေးရှိ {{ui:Documents}} ကို ရွေးပါ၊ သို့မဟုတ် **File** မီနူးရှိ {{ui:Documents…}}။
2. {{ui:Choose the project folder}} ကို ရွေး၍ ပရောဂျက်၏ IFC မော်ဒယ်များ ရှိသော ဖိုင်တွဲကို ရွေးပါ။ (ပရောဂျက်ဖိုင်တွဲများသည် Studio တွင်နှင့် ဖိုင်တွဲဖွင့်နိုင်သော ဘရောက်ဇာများ၊ ဥပမာ Chrome နှင့် Edge တွင် အလုပ်လုပ်သည်။ အခြားဘရောက်ဇာများတွင် အကန့်က ထိုသို့ ပြောသည်။)
3. **You:** ဘေးရှိ {{ui:Change}} ကို ရွေး၍ သင့်အမည် `Ana` ကို ရိုက်ပါ (မေးလျှင် ဤကွန်ပျူတာ၏ အမည်လည်း)။ အကန့်က ယခု *You: Ana on* နှင့် သင့်ကွန်ပျူတာဟု ပြောသည်။ သင့်အမည်သည် သင်လုပ်သမျှအားလုံးတွင် ပါသည်။
4. {{ui:Start a vault in this folder}} ကို ရွေး၍ ပရောဂျက်အမည် `Riverside clinic` ကို ရိုက်ပါ။ အကန့်က *Vault started for Riverside clinic.* ဟု ပြောသည်။

## ၂။ ဖိုင်တစ်ခုကို ထိန်းချုပ်အောက် ထားခြင်း

1. **Files not in the vault** ကို ဖွင့်ပြီး `models/House.ifc` ဘေးရှိ {{ui:Add}} ကို ရွေးပါ။
2. ၎င်းသည် ပြင်ဆင်မှု **A.1**၊ အခြေအနေ **Work in progress** ဖြင့် **Files in the vault** အောက်တွင် ပေါ်လာသည်။ A.1 သည် ၎င်း၏ ပထမမိတ္တူဖြစ်သည်; vault က ပြင်ဆင်မှုတိုင်း၏ မိတ္တူကို သိမ်းသည်။

## ၃။ Check out၊ ပြောင်းလဲ၊ Check in

1. `models/House.ifc` ဘေးရှိ {{ui:Open}} ကို ရွေးပါ။ မော်ဒယ်သည် BimCraft တွင် ဖွင့်ပြီး အကန့်ပိတ်သဖြင့် သင်မြင်နိုင်သည်။ {{ui:Documents}} မှ အကန့်ကို ထပ်ဖွင့်ပါ။
2. အကန့်ကို ထပ်ဖွင့်ပြီး {{ui:Check out}} ကို ရွေးပါ။ အတန်းက ယခု **Checked out to you** ဟု ပြောသည်။ `.ccvault/locks` တွင် lock ဖိုင်တစ်ခု ပြုလုပ်ထားသည်; သင် check in မလုပ်မချင်း တစ်ယောက်မျှ ဤဖိုင်ကို check out မလုပ်နိုင်ပါ။
3. မော်ဒယ်ကို ပြောင်းပါ: နံရံတစ်ခု ရွှေ့ပါ၊ တံခါးတစ်ခု ထည့်ပါ။ မော်ဒယ်သည် သင့်ထံ check out မလုပ်ထားလျှင် Save ကို ငြင်းပယ်ပြီး အကြောင်းပြသည်; Save As သည် သင့်ကိုယ်ပိုင်မိတ္တူအတွက် အမြဲ အလုပ်လုပ်သည်။
4. အကန့်ကို ဖွင့်၊ {{ui:Check in}} ကို ရွေးပြီး ဘာပြောင်းသလဲ ရိုက်ပါ (`Moved the door`)။ အကန့်က *checked in as A.2* ဟု ပြောသည်။ ပရောဂျက်ဖိုင်တွဲရှိ ဖိုင်သည် ယခု သင်ဖွင့်ထားသော မော်ဒယ်ဖြစ်ပြီး lock ပျောက်သွားသည်။ ပြောင်းလဲမှု မရှိဘဲ check in လုပ်လျှင် ပြင်ဆင်မှုကို ထိန်းထားသည်။

အမြင်ပြောင်းလျှင် {{ui:Undo check-out}} က ပြင်ဆင်မှုအသစ်မပါဘဲ ဖိုင်ကို ပြန်ပေးသည်။

## ၄။ သုံးသပ်ခြင်းနှင့် ထုတ်ပြန်ခြင်း

1. {{ui:Send for review}} ကို ရွေးပါ။ အခြေအနေသည် **For review** ဖြစ်ပြီး ဖိုင်သည် ဖတ်ရုံသာ ဖြစ်သည်။
2. အတည်ပြုမီ {{ui:Project settings}} ကို ရွေး၍ အတည်ပြုခွင့်ရှိသူများကို (တစ်ကြောင်းလျှင် အမည်တစ်ခု) ဖော်ပြပါ၊ ဥပမာ `Ben` နှင့် `Carla`၊ နှင့် အတည်ပြုသူသည် ရေးသားသူမဟုတ်သော တစ်ဦးဖြစ်ရမည်ဟု စည်းမျဉ်းကို အမှတ်ခြစ်ပါ။ {{ui:Save settings}} ကို ရွေးပါ။ ယခု vault ကိုယ်တိုင်က တခြားသူများကို ငြင်းပယ်သည်။
3. Ben (သို့မဟုတ် Carla) က {{ui:Approve}} ကို ရွေး၍ အတည်ပြုသူ၏ အမည်ကို ရိုက်သည်။ အခြေအနေသည် **Released** ဖြစ်ပြီး ပြင်ဆင်မှုသည် **A** ဖြစ်လာသည်၊ *approved by* နှင့် အမည်ဖြင့်။ ထုတ်ပြန်ပြီးသော ဖိုင်သည် ဖတ်ရုံသာ ဖြစ်သည်။ {{ui:Send back}} က အကြောင်းပြချက်ဖြင့် Work in progress သို့ ပြန်ပို့ပေးမည်ဖြစ်သည်။

အတည်ပြုသူ၏ အမည်သည် အကန့်တွင် ရိုက်ထည့်သော အမည်ဖြစ်သည်; ၎င်းသည် ဘယ်သူ လက်မှတ်ထိုးသည်ကို မှတ်တမ်းဖြစ်ပြီး၊ မှတ်ပုံတင်အထောက်အထား မဟုတ်ပါ။

## ၅။ ပြင်ဆင်မှုအသစ်

1. ထုတ်ပြန်ပြီးသော ဖိုင်ပေါ်တွင် {{ui:New revision}} ကို ရွေးပါ။ နောက်အက္ခရာအတွက် ၎င်းကို သင်ကိုင်ထားသည်။
2. ပြောင်းပြီး {{ui:Check in}}။ ပြင်ဆင်မှုသည် **B.1**၊ work in progress ဖြစ်သည်။ အတူတူ ထုတ်ပြန်လျှင် **B** ဖြစ်လာမည်။ ပထမ check-in မတိုင်မီ {{ui:Undo check-out}} သည် **A** တွင် ထားသည်။

ပြင်ဆင်မှု အက္ခရာများသည် A၊ B … Z၊ AA၊ AB ဖြင့် ဆက်သွားသည်။ သင့်စံနှုန်းက အက္ခရာအချို့ ချန်ထားလျှင်၊ ပရောဂျက်ဆက်တင် *ASME Y14.35 အစဉ်ကို သုံးရန်* က နောက်ပြင်ဆင်မှုများအတွက် I၊ O၊ Q၊ S၊ X နှင့် Z ကို ကျော်သည်။

## ၆။ ဘာဖြစ်သွားသလဲ ကြည့်ပါ

ဖိုင်အမည်ကို ရွေး၍ အသေးစိတ်ကို ဖွင့်ပါ:

- **{{ui:History}}**: အဖြစ်အပျက်အားလုံး၊ နောက်ဆုံးက ရှေ့ဆုံး၊ ဘယ်သူ၊ ဘယ်ကွန်ပျူတာနှင့် ဘယ်အချိန်: Ana မှ *Checked in A.2*၊ Ben မှ *Released* စသည်။
- **{{ui:Revisions}}**: ပြင်ဆင်မှုဇယား: သိမ်းထားသော ပြင်ဆင်မှုတိုင်း၊ ၎င်း၏ရက်စွဲ၊ ဘယ်သူ check in လုပ်သည်၊ မှတ်ချက်နှင့် ဘယ်သူ အတည်ပြုသည်။ vault က တစ်ခုစီ၏ မိတ္တူကို `.ccvault/revs` တွင် သိမ်းသည်။
- **{{ui:Uses}}**: IFC မော်ဒယ်က ညွှန်ပြသော စာရွက်စာတမ်းများ။
- **{{ui:Used by}}**: ဤဖိုင်ကို ညွှန်ပြသော vault ရှိ မော်ဒယ်အားလုံးကို ဖော်ပြသည်။

## အခြားစာရွက်စာတမ်းများကို ညွှန်ပြသော မော်ဒယ်များ

ဖိုင်တွဲရှိ အခြားစာရွက်စာတမ်းများ (ပုံဆွဲများ၊ ဇယားများ) ကို ညွှန်ပြသော IFC မော်ဒယ်သည် **Uses** အောက်တွင် ၎င်းတို့ကို ပြသည်၊ ထိုစာရွက်စာတမ်းတစ်ခုစီသည် **Used by** အောက်တွင် မော်ဒယ်ကို ပြသည်။ စာရွက်စာတမ်းတစ်ခုကို check in လုပ်လျှင် မည်သည့်မော်ဒယ်များက ၎င်းကို ရည်ညွှန်းသည်ကို မြင်နိုင်သည်။

## ၇။ သင်ဖိုင်ကိုင်ထားစဉ် Ben ဘာမြင်သလဲ

ယခု ဖိုင်ကို ထပ်မံ check out လုပ်ပြီး Ben ကို သူ၏ကွန်ပျူတာတွင် တူညီသော ပရောဂျက်ဖိုင်တွဲကို ဖွင့်ပြီး အကန့်ကို ဖွင့်ရန် တောင်းဆိုပါ။ ဖိုင်၏အတန်းတွင် သူသည် **Checked out by Ana on** သင့်ကွန်ပျူတာနှင့် အချိန်ကို **since** ဟု မြင်ပြီး {{ui:Check out}} ခလုတ် မရှိပါ။ သူ ကြိုးစားလျှင်လည်း vault က ငြင်းပယ်သည်: lock သည် စနစ်က နှစ်ကြိမ် မပြုလုပ်မည့် ဖိုင်ဖြစ်သောကြောင့်၊ ဖိုင်တွဲသည် Studio တွင် disk ပေါ်ရှိသည့်အခါ၊ လူနှစ်ဦးက တစ်စက္ကန့်တည်းတွင်ပင် ဖိုင်ကို နှစ်ဦးလုံး ကိုင်ထားနိုင်မည် မဟုတ်ပါ။ (ဘရောက်ဇာတွင် ဖိုင်တွဲက အကောင်းဆုံး ကြိုးစားမှုသာ ခွင့်ပြုပြီး၊ အကန့်က **Folder** အောက်တွင် ထိုသို့ ပြောသည်။)

Ana မရှိပြီး Ben ဖိုင် လိုအပ်လျှင် {{ui:Break check-out}} က လွတ်စေသည်။ သူ အကြောင်းပြချက် ရိုက်ရမည်; ၎င်းသည် ဘယ်သူ၏ check-out ဖြစ်သည်ကို မှတ်တမ်းတွင် ထည့်သည်။ ပရောဂျက်က admin များကို စာရင်းပြုထားလျှင် ထိုသူတို့သာ လုပ်နိုင်သည်။ stale limit (မူလ 14 ရက်) ထက်ဟောင်းသော check-out ကို *a long time* ဟု အမှတ်အသားပြုသည်။ ဖြတ်ပြီးနောက် Ana ၏ နောက်ကျသော check-in ကို ငြင်းပယ်သည်၊ ထို့ကြောင့် သင်နှစ်ယောက် တစ်ယောက်ကို တစ်ယောက် အစားထိုး မရေးနိုင်ပါ။

## ၈။ Cloud ဖိုင်တွဲများ

Cloud ဖိုင်တွဲသည် သင်၏အဖွဲ့ cloud သိုလှောင်မှုတွင် ထားသော ပရောဂျက်ဖိုင်တွဲဖြစ်သဖြင့် အဖွဲ့သည် shared drive မလိုအပ်ပါ။ CadCraft အကောင့်ဖြင့် ဝင်ထားသော Studio တွင်၊ အကန့်က {{ui:Choose the project folder}} ဘေးတွင် {{ui:Open a cloud folder}} ကို ပြသည်။ ထိုကို ရွေး၍ ဖိုင်တွဲကို ရွေးပါ၊ workspace / folder အဖြစ် စာရင်းပြုထားသည်။ workspace ပိုင်ရှင်က ဖိုင်တွဲကို ရှေ့ဦးစွာ ပြုလုပ်ရမည်၊ နှင့် အဖွဲ့၏ cloud သိုလှောင်မှုသည် ထိရောက်ရမည်။ အထက်ပါအရာအားလုံး တူညီစွာ အလုပ်လုပ်သည်; ဆာဗာက lock ကို ပြုလုပ်ပြီး လူများကြား တင်းကျပ်သည်။ ဝင်မထားလျှင် အကန့်က ဝင်ရန် ပြောသည်။ ပုံမှန် ဘရောက်ဇာတဘ်တွင် cloud ခလုတ် မပေးပါ; Studio ကို သုံးပါ။

## စမ်းကြည့်ပါ

အထက်ပါ ရှစ်ဆင့်ကို အစစ်အမှန် ဖိုင်တစ်ခု၏ မိတ္တူဖြင့် လုပ်ပါ။ လူနှစ်ဦးအဆင့်များအတွက် တခြားလူတစ်ဦး၊ သို့မဟုတ် အမည်နှစ်ခုဖြင့် ဝင်းဒိုးနှစ်ခု လိုအပ်သည်။ အစစ်အမှန် shared ဖိုင်တွဲဖြင့် စမ်းလျှင်၊ အသိုင်းအဝိုင်း စမ်းသပ်ရေးစာမျက်နှာတွင် ဤအရာကို အတိအကျ မေးသော စစ်ဆေးချက်ရှိပြီး ရလဒ်များကို လက်ခံသည်။
