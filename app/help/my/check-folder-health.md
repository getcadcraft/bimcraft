## ဘာလုပ်မလဲ

ပို့ပေးမီ သို့မဟုတ် အလုပ်မစမီ ပရောဂျက်ဖိုင်တွဲကို စစ်ဆေးပါ- မော်ဒယ်တိုင်း ပြည့်စုံလား၊ နောက်ဆုံး ကောင်းမွန်သော အရန်ဘယ်ဟာလဲ၊ ချိတ်ဆက်ထားသော ဖိုင်များ အားလုံး ရှိလား။

## အဆင့်များ- ပျက်စီးသော မိတ္တူများ

1. ပရောဂျက်ဖိုင်တွဲကို ဖွင့်ပါ။ [ပရောဂျက် ဖိုင်တွဲတစ်ခုလုံးကို ဖွင့်ခြင်း](topic:open-project-folder) ကို ကြည့်ပါ။
2. ဖိုင်တွဲအမည်အောက်ရှိ မှတ်ချက်များကို ဖတ်ပါ။ "ဖိုင် ၂ ခု မပြည့်စုံ သို့မဟုတ် ဖတ်၍မရပါ။ အောက်ရှိ မော်ဒယ်များကို ကြည့်ပါ။" ဆိုသည်မှာ စစ်ရန် အရာရှိသည်ဟု ဆိုလိုသည်။
3. **Models** တွင် **Status** ကော်လံကို ကြည့်ပါ။ **ပြည့်စုံ** သည် ကောင်းသည်။ အဝါရောင် "1 မပြည့်စုံ" သည် မိတ္တူတစ်ခု ပျက်နေသော်လည်း နောက်တစ်ခု ကောင်းနေကြောင်း ဆိုလိုသည်။ အနီရောင် **မပြည့်စုံ** သည် ကောင်းသော မိတ္တူတစ်ခုမျှ မတွေ့ကြောင်း ဆိုလိုသည်။
4. ပြဿနာရှိသော မော်ဒယ်အောက်ရှိ **မိတ္တူ … အားလုံး** ကို ဖွင့်ပါ။ ၎င်းသည် အဓိကဖိုင်နှင့် နံပါတ်တပ်ထားသော အရန်အားလုံးကို အသစ်ဆုံး အရင်ဖြင့် ဆိုဒ်၊ ရက်စွဲနှင့် အခြေအနေတို့ဖြင့် စာရင်းပြုသည်။
5. စာရင်းအပေါ်ရှိ မှတ်ချက်ကို ဖတ်ပါ၊ ဥပမာ- "Tower.rvt မပြည့်စုံပါ (183.2 MB၊ အနည်းဆုံး 214.0 MB ရှိရမည်)။ ကတ်တွင် အသစ်ဆုံး ပြည့်စုံသော မိတ္တူ Tower.0012.rvt (Mar 3, 2025) ကို ပြသည်။"
6. သင်ဖွင့်လိုသော မိတ္တူကို နှိပ်ပါ။ ပြည့်စုံသော မိတ္တူများကိုသာ နှိပ်နိုင်သည်။

## ကျန်းမာရေး စစ်ဆေးခြင်း ဘာလုပ်သလဲ

မော်ဒယ်တစ်ခုစီ၏ မိတ္တူတိုင်းကို ခေါင်းစီးရှိ ဘိုက် 512 စီဖြင့် အမြန် စစ်ဆေးသည်၊ ထို့ကြောင့် မော်ဒယ်ကြီးများ ပါသော ဖိုင်တွဲတစ်ခုတောင် စက္ကန့်ပိုင်းအတွင်း စစ်ဆေးသည်။ ဖိုင်၏ ကိုယ်ပိုင် အညွှန်းက ၎င်း အဆုံးကို ကျော်နေပါက ကူးယူ၊ အပ်လုဒ်လုပ်ခြင်း သို့မဟုတ် ထပ်တူပြုခြင်းအတွင်း ဖြတ်တောက်ခံခဲ့ရသည်။ "online only" ဖြစ်နေသော cloud-drive ဖိုင်လည်း တူညီစွာ ပေါ်သည်။

မော်ဒယ်တစ်ခု၏ ကတ်ကို ကျန်းမာသော ဖြစ်လျှင် အဓိကဖိုင်မှ၊ မကျန်းမာလျှင် နောက်ဆုံး ကောင်းသော အရန်မှ ဖတ်သည်။

## အဆင့်များ- ပျောက်နေသော လင့်ခ်များ

1. ဖိုင်တွဲအမည်အောက်တွင် "*n* linked files are not in this folder." ဆိုသော မှတ်ချက်ကို ရှာပါ။
2. **Linked and referenced files** သို့ လှိမ့်ပါ။ ပျောက်နေသော လင့်ခ်များကို ဦးစွာ ဖော်ပြသည်။
3. လင့်ခ်တစ်ခုစီအတွက် **Where** ကော်လံကို ဖတ်ပါ-
   - **In this folder**: မော်ဒယ်က သိမ်းခဲ့သော လမ်းကြောင်းတွင် တွေ့သည်။
   - **Same name found**: အမည်တူ ဖိုင်တစ်ခုသည် ဖိုင်တွဲ၏ အခြားနေရာတွင် ရှိသည်။ မှန်ကန်သော ဖိုင်ဖြစ်ကြောင်း စစ်ပါ။
   - **Library file**: keynote သို့မဟုတ် assembly code ဇယား။ ၎င်းတို့သည် ကွန်ပျူတာတိုင်းတွင် ပရိုဂရမ်နှင့်အတူ ပါလာသဖြင့် ဖိုင်တွဲတွင် မမျှော်လင့်ပါ။
   - **Not in this folder**: ဖိုင်တွဲတစ်ခုလုံးတွင် ဘယ်နေရာမှ မတွေ့ပါ။
4. ဖိုင်တစ်ခုစီကို ချိတ်ဆက်ထားသော မော်ဒယ်များကို သိရန် **Used by** ကို ဖတ်ပါ။

BimCraft သည် လင့်ခ်တစ်ခုစီကို ဦးစွာ ဆွေမျိုးလမ်းကြောင်းဖြင့်၊ ထို့နောက် သိမ်းထားသော လမ်းကြောင်း၏ အဆုံးဖြင့် (ဥပမာ `\\server\jobs\Tower\Cad\X-Refs\site.dwg` ကို `Cad` ဖိုဒါကို ရွေးချိန်တွင် `X-Refs/site.dwg` တွင် တွေ့သည်)၊ ထို့နောက် ဖိုင်တွဲအတွင်း ဘယ်နေရာမဆို ဖိုင်အမည်ဖြင့် ရှာသည်။

## အဆင့်များ- အကြွင်းအကျန်များ

1. အစီရင်ခံစာ၏ အဆုံးရှိ **Set aside** သို့ လှိမ့်ပါ။
2. ပေါ်နိုင်သော စာကြောင်း သုံးကြောင်းကို ဖတ်ပါ-
   - အထောက်အကူ ဖိုင်တွဲများ (`*_backup`, `*_log`, `Revit_temp`): မဖတ်ပါ။
   - လော့ခ်၊ log နှင့် အရန် အကြွင်းအကျန်များ: `.dwl`, `.dwl2`, `.bak`, `.err`, `.log`, `.tmp`, `.sv$` ကဲ့သို့ ဖိုင်များ။ ၎င်းတို့သည် ပျက်ကျသွားသော သို့မဟုတ် ဖိုင်တွဲကူးစဉ် ဖွင့်ထားသော ပရိုဂရမ်များက ကျန်ခဲ့သည်။ ဘယ်သူမျှ ဖိုင်များကို ဖွင့်မထားသည့်အခါ ဖျက်ရန် များသောအားဖြင့် ဘေးကင်းသည်။
   - အခြားဖိုင်များ: BimCraft မဖတ်သော အခြားအရာအားလုံး။

## သတိထားရမည့် အမှားများ

- **ကောင်းသော အရန်ကို မသိမ်းမီ ပျက်စီးသော အဓိကဖိုင်ကို ဖျက်ခြင်း။** ဦးစွာ နောက်ဆုံး ပြည့်စုံသော အရန်ကို ကူးပါ၊ ထို့နောက် ပျက်စီးသော ဖိုင်ကို ကိုင်တွယ်ပါ။
- **"Same name found" ကို မစဉ်းစားဘဲ ယုံခြင်း။** ပုံဆွဲနှစ်ခုသည် အမည်တူနိုင်သည်။ သံသယရှိလျှင် နှစ်ခုလုံးကို ဖွင့်ပါ။
- **ပျောက်နေသော library ဖိုင်ကို ပြဿနာဟု ထင်ခြင်း။** Keynote နှင့် assembly code ဇယားများသည် ကွန်ပျူတာတိုင်းတွင် ပရိုဂရမ်နှင့်အတူ နေသည်။
- **ဖိုင်အရေအတွက် ဘရောက်ဆာအလိုက် ကွဲပြားခြင်း။** Firefox နှင့် Safari တွင် {{ui:ဖိုဒါ ဖွင့်ရန်}} သည် အထောက်အကူ ဖိုင်တွဲများအတွင်းရှိ ဖိုင်များအပါအဝင် ဖိုင်အားလုံးကို ပေးသဖြင့် အရေအတွက် (နှင့် ဖိုင် 20,000 ကန့်သတ်ချက်) တွင် ၎င်းတို့ ပါဝင်သည်။ ဖိုင်တွဲကို ဆွဲယူလျှင် Chrome နှင့် Edge ကဲ့သို့ ၎င်းတို့ကို ကျော်သည်။ အစီရင်ခံစာမှာ အခြားအရာ တူညီသည်။
