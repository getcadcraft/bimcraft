## ဘာလုပ်မလဲ

သင့် wall type များကို ပရောဂျက်တစ်ခုမှ တစ်ခုသို့ သယ်ပါ၊ သို့မဟုတ် အခြားပရိုဂရမ်တွင် အလုပ်လုပ်သူထံ ပေးပါ။ type pack သည် wall type တစ်ခုစီ၏ layer များ၊ အထူများ၊ material များ၊ core၊ cavity များ၊ layer priority၊ development အဆင့်၊ takeoff ဒေတာနှင့် classification ကုဒ်များ၊ နှင့် သင်ထည့်သော family များကို ထိန်းသည်။ ၎င်းသည် ဖွင့်ဖိုင်ဖြစ်သည်: ဘယ်သူမဆို ဖတ်နိုင်သော plain JSON စာသား၊ သို့မဟုတ် IFC ဖိုင်။ ကုမ္ပဏီ၊ နိုင်ငံ သို့မဟုတ် အကောင့်တစ်ခုခုတွင် ပိတ်ထားခြင်း မရှိပါ။

## ပရောဂျက်မှ အမျိုးအစားများ သိမ်းခြင်း

1. မော်ဒယ်ဘားရှိ **Data** ကို ဖွင့်ပြီး {{ui:အမျိုးအစား အစုအဝေးများ}} ကို ရွေးပါ။
2. {{ui:ဤပရောဂျက်မှ အမျိုးအစားများကို သိမ်းရန်}} အောက်တွင် ထည့်လိုသော wall type များကို အမှတ်ခြစ်ပါ။ ပရောဂျက်၏ ကိုယ်ပိုင် type များကို အမှတ်ခြစ်ထားပြီး starter type ကို ထည့်နိုင်ပြီး မိတ္တူအဖြစ် ထည့်သည်။ family များ ထည့်လိုလျှင် အမှတ်ခြစ်ပါ။
3. {{ui:ပက်အမည်}} ကို ရိုက်ပါ။
4. {{ui:ပက် (.json) အဖြစ် သိမ်းရန်}} က `.cctypes.json` ဖိုင် ဒေါင်းလုဒ်လုပ်သည်။ {{ui:IFC (.ifc) အဖြစ် သိမ်းရန်}} က type သာ ပါသော IFC ဖိုင် ဒေါင်းလုဒ်လုပ်သည်: wall type တစ်ခုစီကို material layer set၊ material နှင့် classification ပါသော IfcWallType အဖြစ်၊ ဘယ် BIM ပရိုဂရမ်အတွက်မဆို။

## ပရောဂျက်သို့ အမျိုးအစားများ ထည့်ခြင်း

1. ထိုဒိုင်ယာလော့တွင် {{ui:ပက် သို့မဟုတ် IFC ဖိုင် ဖွင့်ရန်…}} ကို ရွေးပြီး `.json` pack သို့မဟုတ် `.ifc` ဖိုင် ရွေးပါ။
2. ဒိုင်ယာလော့က ဖိုင်တွင်ပါသည်များကို စာရင်းပြသည်: wall type တစ်ခုစီ၏ အထူ၊ layer အရေအတွက်နှင့် ကုဒ်များ၊ material များနှင့် family များ။
3. {{ui:ပရောဂျက်တွင် ရှိပြီးသား အမျိုးအစား}} ကို ဘာလုပ်မည်ကို ရွေးပါ: **ပရောဂျက်၏ကို ထိန်းမည်**၊ **pack ၏ကို မိတ္တူအဖြစ် ထည့်မည်** (အမည်အသစ် "(2)" ဖြင့် အဆုံးသတ်သည်)၊ သို့မဟုတ် **အစားထိုးမည် (နံရံမသုံးထားမှသာ)**။
4. {{ui:ပရောဂျက်သို့ ထည့်ရန်}}။ ဒိုင်ယာလော့က ထည့်ခဲ့သော၊ မိတ္တူပြုခဲ့သော၊ အစားထိုးခဲ့သော သို့မဟုတ် ထားခဲ့သည်များကို ပြသည်။ ၎င်းသည် undo အဆင့်တစ်ခု ဖြစ်သည်။

အသစ် type များသည် Wall ကိရိယာ၏ type စာရင်းတွင် ချက်ချင်း ရှိနေသည်။

## Floor၊ roof နှင့် ceiling type များ

သိမ်းရန် type စာရင်းတွင် ပရောဂျက်၏ floor၊ roof နှင့် ceiling type များနှင့် ၎င်းတို့၏ starter များ (Floor၊ Roof၊ Ceiling ဟု အမှတ်အသားပြုထား) လည်း ပါဝင်သည်။ pack တစ်ခုက အမျိုးအစား လေးမျိုးလုံး သယ်နိုင်သည်; type တစ်ခုစီသည် ၎င်း၏ IFC class (IfcWallType၊ IfcSlabType၊ IfcCoveringType) ကို အမည်ပေးသည်။ ဒြပ်စင်များ သုံးနေသော floor၊ roof သို့မဟုတ် ceiling type ကို pack မှ မအစားထိုးပါ: type editor တွင် ပြောင်းပါ။

## Library ပစ္စည်းတစ်ခုအဖြစ် type တစ်ခု

type တစ်ခုတည်းကို အမှတ်ခြစ်ပြီး **Library ပစ္စည်းအဖြစ် သိမ်းရန်…** ကို ရွေးပါ။ ၎င်းသည် `.cctype.json` ဖိုင်တစ်ခု သိမ်းသည်: Types အမျိုးအစား Library ပစ္စည်းတစ်ခုဖြစ်ပြီး type တစ်ခုတည်း (layer၊ material၊ LOD နှင့် classification ကုဒ်များ) ပါဝင်သည်။ မျှဝေရန် Library တွင် တင်ပါ။ **ပက် သို့မဟုတ် IFC ဖိုင် ဖွင့်ရန်** သည် ထိုပစ္စည်းကိုလည်း ဖတ်ပြီး pack ကဲ့သို့ ၎င်း၏ type ကို ပရောဂျက်သို့ ထည့်သည်။

## သိထားသင့်သည်များ

- အခြားပရိုဂရမ်မှ IFC ဖိုင်ကိုလည်း ဤနေရာတွင် ဖွင့်နိုင်သည်။ material layer ရှိသော wall type တိုင်းကို ဖတ်သည်: အမည်၊ layer များ၏ material နှင့် အထူနှင့် cavity များသည် ဖိုင်၏ ကိုယ်ပိုင်ဖြစ်သည်။ core ဖြစ်သော layer များနှင့် layer တစ်ခုစီ၏ လုပ်ဆောင်ချက် (finish၊ structure၊ insulation) ကို ခန့်မှန်းသည်၊ type ကို **(ခန့်မှန်း)** ဟု အမှတ်အသားပြုပြီး wall type editor တွင် စစ်ဆေးသင့်သည်။ layer မရှိသော wall type ကို ချန်လှပ်ပြီး အမည်ပေးသည်။
- ပရောဂျက်တွင် ရှိပြီးသား material ကို ထားသည်။ အမည်ထပ်နေသော material အသစ်သည် အမည်နောက်တွင် "(pack)" ရရှိသည်။
- wall သုံးနေသော type ကို pack မှ ဘယ်တော့မှ မအစားထိုးပါ။ wall type editor တွင် ပြောင်းပါ၊ ၎င်းသည် နံရံများကို သင့်တော်စွာ ရွှေ့သည်။
- wall တစ်ခုပေါ်တွင် သတ်မှတ်ထားသော ကုဒ်သည် မသယ်ပါ: ၎င်းသည် ထို wall နှင့်သာ ဆိုင်သည်။ type ပေါ်တွင် သတ်မှတ်သော ကုဒ်သည် သယ်သည်။
- ဖော်မတ်တွင် မရှိသော field ပါသော ဖိုင်၊ material မရှိသော layer၊ သို့မဟုတ် plain text မဟုတ်သည်တစ်ခုခုကို ငြင်းပယ်ပြီး မက်ဆေ့ချ်က ဘယ်နေရာနှင့် အဘယ်ကြောင့်ကို ပြောသည်။
- ယခုထိ မပြုလုပ်ရသေးသည်: floor၊ roof နှင့် ceiling type များ (ဤဗားရှင်းတွင် type မရှိ: တစ်ခုစီသည် ကိုယ်ပိုင်အထူရှိသည်)၊ family မဟုတ်သော door နှင့် window type များ၊ နှင့် အခြားပရိုဂရမ်ဖိုင်မှ hatch သို့မဟုတ် အရောင်များ။
